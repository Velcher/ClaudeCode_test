## 1. 背景：为什么 ARM 要搞 SME

机器学习在终端设备上的普及改变了芯片设计的游戏规则。过去十年，ARM 的 NEON 和 SVE 在通用 SIMD 场景下表现不错，但当矩阵规模从 4×4 扩展到 64×64 甚至更大时，传统向量 ISA 的瓶颈暴露了：

- **寄存器是 1D 的**：SVE 的 Z 寄存器最长 2048 位，方向是一维的，矩阵计算需要大量重排操作
- **MAC 延迟高**：一条 `fmla` 负责一个元素乘累加，64×64 矩阵需要数千条指令
- **访存压力大**：每个输出元素要遍历整个 K 维度，cache 抖动严重

2021 年，ARM 在 v9-A 架构中正式发布 **SME（Scalable Matrix Extension）**。它不是 SVE 的简单升级，而是引入了一个全新的二维执行模型。动机很明确：**给 CPU 装一个矩阵引擎，让它能与专用加速器（GPU、NPU）在低延迟推理场景下竞争。**

## 2. SME 架构速览

SME 的核心组件：

**ZA（Z Array）— 二维累加寄存器**

ZA 是 SME 的灵魂。它是一个二维的寄存器阵列，尺寸由 SVL（流向量长度）决定。以 SVL=256 为例，单精度下 `svcntw=8`，ZA 为 8×8 floats；双精度下 `svcntd=4`，ZA 为 4×4 doubles。

```
ZA 存储布局（SVL=256, float64）：
┌──────────────────┐
│   4×4 doubles    │  ← 一个 FMOPA tile 刚好覆盖整个 ZA
│  共 16 个元素     │
└──────────────────┘
每个 Z 寄存器装 4 个 double
```

**Streaming SVE 模式**

进入 SME 后（`smstart`），CPU 切换到 Streaming SVE 模式。这个模式下：
- SVE 向量长度拉伸到与 ZA 宽度匹配
- 部分 NEON/SVE 指令不再可用
- 所有向量加载围绕 ZA tile 对齐

## 3. FMOPA 指令详解

`FMOPA` 是 SME 的核心外层积指令。汇编语法：

```
fmopa za.d[0], p0/m, p0/m, z0.d, z1.d
```

- `za.d[0]` — 目标 ZA tile（双精度用 `.d` 后缀）
- `p0/m` — 合并谓词：p0 为真的通道执行乘累加，为假的通道保持 ZA 原值
- `z0.d` — 行向量（double 类型）
- `z1.d` — 列向量（double 类型）

**语义**：`ZA[i][j] += z0[i] × z1[j]`

每个 z0[i] 与 z1[j] 的所有组合做积，结果累加到 ZA tile 对应位置。这就是**外层积**的核心 — 一条指令完成 4×4=16 个 double 的乘累加。累加内建于 FMOPA 指令中（A = Accumulate），无需额外的加法指令。

**硬件视角**：

```
z0 = [a0, a1, a2, a3]   (4 doubles)
z1 = [b0, b1, b2, b3]   (4 doubles)

ZA += ┌──────────────────────────┐
      │ a0b0  a0b1  a0b2  a0b3  │
      │ a1b0  a1b1  a1b2  a1b3  │
      │ a2b0  a2b1  a2b2  a2b3  │
      │ a3b0  a3b1  a3b2  a3b3  │
      └──────────────────────────┘
        4×4 outer product
```

## 4. 外层积 vs 点积：数学推导

**点积（内积）方式**：传统 `C[i][j] = Σ_k A[i][k] * B[k][j]` — 每个输出元素需要一个完整的 K 维归约循环。

**外层积方式**：C 看做出 A 的每一列和 B 的每一行的外层积之和：

```
C = Σ_k (A_col_k ⊗ B_row_k)
```

Fmopa 一条指令完成一整个 block 的 MAC 操作。对 8×8 矩阵，8 次 FMOPA 覆盖全部 512 次乘加运算（单精度），指令数从 4096 次 `fmla` 降到 8 次 `FMOPA`。

## 5. 巧妙的优化：C = A^T × B 消除 gather

常规的 `C = A × B` 需要从 A 取**列**向量。row-major 存储下，列元素在内存中不连续 — `&A[i][k]` 与 `&A[i+1][k]` 间隔 8 个 float，需要 gather 加载（INDEX + UXTW 寻址）。

但如果计算 `C = A^T × B`：

```
C[i][j] = Σ(k) A^T[i][k] × B[k][j] = Σ(k) A[k][i] × B[k][j]
```

A^T 的列 = A 的行 — 而 A 的行在内存中**连续**！于是每次 FMOPA：
- z0 = A 的第 k 行（连续加载，无 gather）
- z1 = B 的第 k 行（连续加载，无 gather）

省去：INDEX 指令、UXTW #2 寻址模式、z2 gather 偏移寄存器。结果是更简洁、更快的 K 循环。

```
原来:  ld1w {z0.s}, p0/z, [x4, z2.s, uxtw #2]   ← gather
现在:  ld1d {z0.d}, p0/z, [x4]                    ← 连续
```

## 6. 双精度 8×8 实现

双精度下 VL=256 时 `svcntd=4`，ZA.d 只有 4×4，一个 tile 装不下 8×8。将 8×8 输出拆成 4 个象限，分 4 趟计算：

```
┌───────────────┬───────────────┐
│ 趟 0: i=0..3  │ 趟 1: i=0..3  │
│      j=0..3   │      j=4..7   │
├───────────────┼───────────────┤
│ 趟 2: i=4..7  │ 趟 3: i=4..7  │
│      j=0..3   │      j=4..7   │
└───────────────┴───────────────┘
```

每趟：zero ZA → K 循环取对应象限的 A/B 行的一半 → fmopa → 写回 ZA 4 行。

```asm
// 进入 SME + 生成谓词
smstart
ptrue  p0.d, vl4           // 4 doubles 全激活

// === 趟 0: C[0:3][0:3] ===
zero   {za}
mov    x3, #0
.Lq00_loop:
    add    x4, %[A], x3, lsl #6        // &A[k][0]  (一行 8 doubles = 64 bytes)
    ld1d   {z0.d}, p0/z, [x4, #0, mul vl]  // A[k][0..3]
    add    x5, %[B], x3, lsl #6
    ld1d   {z1.d}, p0/z, [x5, #0, mul vl]  // B[k][0..3]
    fmopa  za.d[0], p0/m, p0/m, z0.d, z1.d // ZA += outer(z0, z1)
    add    x3, x3, #1
    cmp    x3, #8
    b.ne   .Lq00_loop

// 写回象限 0 → C[0..3][0..3]
mov    x7, %[C]
mov    z0.d, p0/m, za.d[0]
st1d   {z0.d}, p0, [x7, #0, mul vl]    // C[0][0..3]
add    x7, x7, #64
mov    z0.d, p0/m, za.d[1]
st1d   {z0.d}, p0, [x7, #0, mul vl]    // C[1][0..3]
add    x7, x7, #64
mov    z0.d, p0/m, za.d[2]
st1d   {z0.d}, p0, [x7, #0, mul vl]    // C[2][0..3]
add    x7, x7, #64
mov    z0.d, p0/m, za.d[3]
st1d   {z0.d}, p0, [x7, #0, mul vl]    // C[3][0..3]

// === 趟 1: C[0:3][4:7] ===
//   z0 = A[k][0..3], z1 = B[k][4..7] (ld1d offset #1)
//   写回到 C + 32 (跳过前 4 doubles)
//   (结构同上, 8 行代码)

// === 趟 2: C[4:7][0:3] ===
//   z0 = A[k][4..7] (ld1d offset #1), z1 = B[k][0..3] (offset #0)
//   写回基准 C + 256 (跳过前 4 行)

// === 趟 3: C[4:7][4:7] ===
//   z0 = A[k][4..7] (offset #1), z1 = B[k][4..7] (offset #1)
//   写回基准 C + 288 (跳过前 4 行 + 前 4 doubles)

smstop
```

完整代码见 `smau/sme_double_test.c`。

**写回寻址说明**

C 矩阵 row-major，每行 8 doubles = 64 bytes。mul vl 乘的是 VL 字节数（32 bytes），所以：
- `[xC, #0, mul vl]` = C + 0（行首）
- `[xC, #1, mul vl]` = C + 32（行中）

象限 0 写 C[0:3][0:3]：依次写 xC、xC+64、xC+128、xC+192
象限 1 写 C[0:3][4:7]：基准 xC+32，防止覆盖象限 0 的结果

## 总结

| 设计选择 | 原因 |
|------|-----------|
| C = A^T × B | 消除 gather，A 的列变为 A 的行，连续加载 |
| LD1D / ST1D | 双精度连续访存，无需 INDEX + UXTW |
| 4 趟象限法 | svcntd=4 时 ZA.d 只有 4×4，需分趟覆盖 8×8 |
| FMOPA 内建累加 | 一条指令完成外积 + 累加，无需额外加法 |

完整的 8×8 双精度 SME 实现中，K 循环一共 32 次 FMOPA（4 趟 × 8 次），全程零 gather、零 predication 开销、零索引寄存器。

理解指令集的收益不是记住指令名，而是**搞清楚每一步在 CPU 内部到底发生了什么** — 哪个硬件单元在忙、哪个在等、哪条依赖链把流水线拉长了。把这些问题想通，代码自然就快了。
